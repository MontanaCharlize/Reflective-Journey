# V0.8 核心对话验收

本机验证日期：2026-10-19。以下区分模拟自动测试、真实模型调用和浏览器操作，不沿用旧版本的测试数量当作本轮证据。

## 自动化与构建

- `npm test`：121 / 121 通过。
- `npm run build`：TypeScript 检查与 Windows 生产构建通过。
- 新增联合决策协议与本机访客访问测试，覆盖自然选择、短选择、反例、修订、撤回、拒绝方向、虚构引文、旧状态清理、重复确认、含糊承接和输出截断。
- 客户端覆盖：AI 自选验证动作、请求不锁定动作、失败不追加模板、原话先保存、恢复一次且不重复、主动本地模式不调用模型、取消处理、分支隔离。
- 原先要求“模型不得改变本地动作”“卡住绕过模型”“模型失败静默回退”的测试按新目标改写；存储、迁移、账户权限和社区隐私测试继续保留。
- 质量修正最多一次，额外调用预留额度，usage 累加，隐藏推理内容不进入返回结果或保存记录。

自动测试使用模拟 Provider，不消耗真实模型额度。这些检查主要验证程序行为，不代表语义理解在所有输入上正确。

## 真实 DeepSeek 验证

使用本机已有配置，未覆盖密钥。真实网络请求与模拟调用分开记录。

| 验证 | 次数与结果 | 限制 |
| --- | --- | --- |
| 独立合成连接检查 | 2 次，HTTP 200 | 只证明连接与 JSON 输出可用 |
| 完全虚构的摄影与阅读对话 | 7 次，均返回模型回应 | 人工审阅发现短选择后的重复确定程度追问；另有一项“尊重方向”的枚举判定未通过，虽然实际回应已避开用户拒绝的方向，不能写成全部质量指标通过 |
| 虚构短选择修正后检查 | 1 次，保留“不参加”的判断，转向条件变化 | 不是所有短回答的完备证明 |
| 经明确授权的截图固定输入回放 | 9 次，未再次索要已经表达的选择 | 原话仅在 `.qa/` 私密报告中保留；授权上限为 12 次，本轮不再继续调用 |
| 正式本机服务 `/api/ai/check` | 1 次成功，返回 deepseek / deepseek-flash | 不含个人思考，只验证重启后的运行进程能访问真实服务 |

截图回放分两部分：先用固定五条回答跟随新问题回放，共 6 次；再在截图原始重复问题的上下文中检查三个关键节点，共 3 次。第二部分更适合验证原问题的修复，因为固定旧回答并不是对新追问的自然回应。

第一部分发现模型将一个指代不明确的简略回答当作能力与效果已经确认，也曾把较笼统的后续表述更新为总体判断。修正后要求区分回答清晰度、保持已有条件立场，并阻止错误的 `initial` 覆盖。原始上下文的复查中，含糊承接被标记 ambiguous，未被当作改主意；最后节点继续保留原本的条件选择。

复查还发现回应段藏着第二个问题，现对 reply 与 question 分开约束，整轮只保留一个问号问题；该边界由模拟回归验证，之后的浏览器虚构对话没有出现第二问。没有为了得到漂亮结果而无限重跑真实原话。

## 浏览器实际操作

使用独立 5194 端口、内存数据库和单独浏览器来源，未打开或读取用户个人思考记录。只输入虚构摄影场景，完成两轮真实模型交互。

1. 首页默认为「AI 共同思考」，配置提示明确区分“已配置”和实际连接成功。
2. 首轮成功后直接显示实际 Provider、模型及“AI 参与理解与决策”。
3. 给出只参加上午、下午休息的选择后，模型分析这个安排的条件与代价，转向“如果主要拍摄安排在下午，应如何调整”的情境检验，没有重新索要选择。
4. 模型没有按本地选择 → 标准 → 取舍的清单机械推进。虚构替代情境明确以“如果”表达，没有写成用户实际经历。
5. 最终构建刷新后从首页重新打开记录，先前的原话、模型回应和参与状态均保留，没有自动追加模型调用。

本机截图：`.qa/v0.8-ai-participation.png`。这是虚构场景的验收证据，不是用户私密记录。独立验收服务在结束后停止，正式服务运行在原来的 5174 地址。

## 当前边界

没有完成真实用户连续 20 分钟使用、不同话题大规模评估或复访验证。自由选择下一步解决了原有固定流程，但不能自动保证每一问都有足够增量。尤其需要继续观察：同一缺口的语义重复、含糊指代、模型假设与用户原话之间的界线。

服务端引用检查和相似度检查只能捕获一部分错误；模型清晰度标签也可能错。本轮结果不能表述成“彻底解决了所有重复与误解”。

社区和语音功能保持现有边界；本轮没有公开个人原话、部署公网、增加点赞评论或扩展社区功能。真实麦克风识别、两台实体设备、公网 HTTPS 与社区真实复访仍未完成验收。
