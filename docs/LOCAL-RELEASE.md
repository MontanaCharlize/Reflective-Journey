V0.10 在 V0.9.1 上补齐社区思考路径、成果回流与运营权限修复。源码交付与运行包仍使用各自入口，旧配置和个人记录沿用；社区变更见 COMMUNITY-V0.10.md。

本版以 V0.8.1 为主干，保留 AI 共同决策、社区接续、语音、随手记和成果导图。新增真实版本的健康检查、跨平台 SQLite 备份恢复、生产启动入口和按清单打包。Kimi 的部署文件已经修正迁入；本次按用户要求交付本地项目，不将公网部署列为完成项。

## 直接运行

Windows 运行包带有官方 Node.js 24.13.1 的 x64 运行程序及许可证。完整解压到普通文件夹，双击「启动项目.bat」。窗口会打开 http://127.0.0.1:5174/，使用期间保留窗口，结束时按 Ctrl+C。

重复启动时，若原地址已有反思之旅，程序显示已有服务版本并打开该页面，不启动当前目录的新副本。端口被其他程序占用则明确提示，可通过「启动项目.bat --port 5177」独立运行。尽量固定使用同一个地址和浏览器，个人记录按浏览器来源保存。运行包无需 npm install；源码包首次运行需要安装依赖并构建。程序不会覆盖现有 .env.local。

运行版的 npm start、npm run dev 和 npm run serve 统一进入正式应用，不启动 Vite，也不自动漂移端口。npm test 和 npm run build 会明确提示改用源码包，并以非零状态结束。运行版的 package.json 不再携带开发依赖；测试与构建只在源码包执行。

没有填写模型配置时，可在首页主动选择「本地提纲」。它不调用 AI，也不会冒充 AI 回应。使用真实模型时，将 .env.example 复制为 .env.local，填写自己的 API Key，重启后在首页「模型连接」验证。公开提交包不包含作者的密钥。

源码运行：npm ci，npm run build，然后 npm start。继续开发时可用 npm run dev。测试使用 npm test。

## 备份与恢复

个人会话、草稿、随手记仍在浏览器，需使用页面的导出功能单独备份。服务端数据库保存账户、公开卡片、收藏、提醒和反馈；下面的数据库工具不会替代浏览器记录导出。

在线数据库备份：

```text
node scripts/database-backup.mjs
```

默认读取配置的数据库，备份保存在数据库旁的 backups 目录，保留最近30份本工具同源备份。备份包含已提交 WAL 内容，校验后封装为一个独立文件。Windows 运行包可将命令中的 node 替换为 runtime\node.exe。

恢复前先停止所有访问数据库的服务，再执行：

```text
node scripts/database-restore.mjs --backup "备份文件完整路径" --confirm-stopped
```

可用 --database 明确指定目标库。工具先校验备份，并在 before-restore 中保留目标库当前状态，再由 SQLite 事务完成恢复。不要手动删除正在使用的 WAL 或 SHM 文件。--confirm-stopped 是操作者对已停服的确认，不能替代实际关闭其他数据库访问进程。

## 部署文件

Dockerfile 的构建阶段保留 evals，运行阶段使用非 root 用户与持久数据卷。compose.yaml 默认只把端口绑定到本机回环地址。正式部署前需要准备 .env.production、实际域名、HTTPS 和持久磁盘，并进行真实环境验收。

Caddy 示例的请求体上限调整为2MB，兼容当前 AI 上下文请求。systemd 示例使用 /var/lib/reflective-journey 保存数据库。配置、镜像、Linux 服务与公网链路不是本轮本地交付的实际运行环境，不能用本地通过结果代替其验收。
