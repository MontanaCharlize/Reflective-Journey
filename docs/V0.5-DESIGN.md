# V0.5：具体反馈、思考支撑与现实验证

## 目标

帮助用户在每次投入中确认一项收获，并把一个值得验证的想法带到真实经历中。功能实现不代表已经证明留存或思考质量提升。

## 一次体验

真实问题 → 一点自己的想法 → 具体回映 → 引擎选择动作 → 一个追问 → 可选提示/换个问法 → 用户主动整理 → 用户确认成果 → 可选小尝试 → 之后回看实际结果。

## 认知边界

- 引擎决定下一动作；模型负责结构化理解和针对性问法。
- 提问不标记动作完成。完成动作来自用户回答，模型新增的标记必须附本轮连续原话，服务端核对引用。
- 引用原话仅证明引用存在，不能自动证明语义判断正确，仍需认知质量评估。
- 纯粹的「不知道」、应答词不会覆盖既有立场，保留当前动作并降低难度。
- 每轮一个思考动作；本地模板和模型输出校验均限制多问题输出。问号数量及清单检查只是初步校验，复杂的语义一致性仍需人工评估。
- 取消六轮强制综合；一条用户回答之后即可主动整理。可以结论不变、仍不确定，也可以保留疑问。
- 反馈描述实际表达，发现和最终判断由用户编辑确认，不提供人格标签或自动能力评分。

## 保存与恢复

schemaVersion = 5，存储键为 reflective-journey/v0.5/sessions，草稿按 session id 隔离存储。

提交回答先保存用户原话和 pendingResponseId，再请求分析与问题。分析完成后也保存检查点。暂停或刷新后，用户从首页或历史打开记录，点击继续这一轮；若已完成分析则跳过，不重复用户原话和分析。

首次提问也先保存原始问题。首次模型处理被打断的记录可重新生成第一问。

服务端模型请求有 20 秒超时，客户端有 25 秒超时；主动取消或断开响应会向服务端 Provider 传播取消信号。失败回退与主动暂停分别处理。

V0.4/V0.3/V0.2 迁移保留原问答、历史分析和旧存储键。当前动作完成集合按用户回答重新推导；历史分析快照作为当时记录保留。

## 思考成果与回访

成果包含初始表达、确认的当前判断、可选收获、待弄清问题、变化和转折点。初始表达是首次非卡住回答，并不保证它一定是一条观点。

验证计划由用户自行填写：一次小尝试及可选观察信号。首页展示最近的进行中记录和最多两条待回看计划，不创建通知或日程。用户回看时追加实际结果和可选的新判断，保留原有成果与此前观察。

提示、换个问法、成果、验证和每次回看均包含在 JSON 导出中，Markdown 导出也列出这些内容。
