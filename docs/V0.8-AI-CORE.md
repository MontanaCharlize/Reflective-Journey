# V0.8：让 AI 参与决策

## 为什么重做核心

旧版有三条互相叠加的失败路径：本地关键词漏掉自然表达的明确选择；本地规划器把未完成的同一动作不断重排；模型被登录、网络或响应错误阻断后，客户端静默追加模板。因此，表面上记录很多“策略选择”，用户实际上没有得到模型的理解和判断。

旧版“本地锁定动作、AI 改写问句”的要求也不足以实现产品目标。V0.8 改成模型共同决定对话目标，而不是只修补识别词。

## 当前主链路

客户端保存原话 → `/api/ai/turn` → 模型一起返回理解、状态证据、目标、回应、下一问 → 服务端检查 → 客户端提交这一轮。

模型收到问题、最近 18 条对话、先前状态与最近目标。动作名只是描述可采用的思考方式，没有固定顺序、必须完成项或通关条件；可以直接转向现实验证、概念区分、具体情境、换方向或整理判断。客户端不会预先锁定动作、目标和追问。

模型的回应可以分析、提供有用区别或暂时解释。对用户心理或经历的假设须明确为可能性；未回答的缺口不能当作已经完成。同一缺口反复没有回应时，应调整入口，而不是换句式继续索要。

## 程序检查什么

- 状态中的引文必须对应真实用户消息，不能引用助手问题或编造原话。
- 对短而有效的选择正常接收；对局部例子、反例和用途解释，不应替换总体选择。`initial` 不能覆盖已有立场。
- 判断修订与撤回保留记录；未知、拒绝方向和跑题不假装完成动作。
- 检查近似重复问题、明确选择后的重复确认、连续索要立场、无内容复述，以及回应里夹带第二问。
- 指代不明确时不能把简略承接当成能力或效果已证实；模型须区分明确理解与暂时解释。
- 不合格候选最多交还模型修正一次，额外调用计入额度；再次失败明确提示，不追加本地模板。

这些约束不是完整的语义证明器。真实引文也可能被误解，模型对回答清晰度和追问增量的判断仍会出错。自动检查与真实对话人工评估需要并行；测试通过不代表任意话题都能保持高质量。

## 失败、恢复与兼容

思考页直接显示模型是否参与及具体错误；可重试、检查连接或主动切换到本地提纲。失败不会丢失原话或伪造下一轮。旧记录可用已有对话重新接入 AI，旧历史不删除；schema 仍为 5，新增字段均可选。

个人本机直连允许访客调用配置好的模型，仍计入全站和分钟额度。校验套接字、Host、Origin 和代理头；代理或公网访问继续要求登录，可用 `AI_ALLOW_LOCAL_GUEST=false` 关闭本机访客能力。社区发布权限保持独立。

DeepSeek 互动任务默认关闭隐藏思考模式，避免结构化输出预算被耗尽；可通过 `DEEPSEEK_THINKING_MODE=enabled` 明确开启。不读取或保存 `reasoning_content`，输出截断明确失败。原有 API Key 和服务商配置不覆盖。

## 隐私与验证边界

完整对话、笔记和调用记录仍属本机个人记录。模型服务与社区公开是两条路径；模型上下文不包含随手记、草稿、社区账号资料或调用日志。社区仍只接收预览确认的成果卡片副本，新接续仍从空认知状态开始。

本轮真实截图回放仅在用户明确同意后进行，最多 12 次，实际 9 次。原话与完整回放保存在被排除的本机 `.qa/`，不随源码或社区公开。验收说明只记录行为与限制，不公开个人原话。
