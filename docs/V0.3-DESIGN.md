# 反思之旅 V0.3 设计说明

## 本轮唯一核心目标

让系统的下一问真正从用户刚刚说过的话里长出来，同时完整保存“问题 → 用户回答 → 结构化认知分析 → 认知动作选择 → 针对性追问 → 用户修正 → 最终判断”的全过程。

## 三层架构

1. **认知状态层**：保存用户当前表达过的判断、焦点、证据线索、替代解释、边界、目标、不确定性和观点变化。
2. **认知策略层**：根据问题类型和当前认知状态选择下一步认知动作；顺序受 playbook 约束，但会跳过用户已经自然完成的动作。
3. **提问生成层**：把“认知动作”改写成针对当前上下文的一问；问题会引用用户刚刚表达的焦点，而不是使用完全固定的问题模板。

## 全过程保存

V0.3 的 ThinkingSession 新增：

- `cognitiveState`：当前结构化认知状态
- `analyses`：每次用户回答后的结构化分析快照
- `plannerRecords`：每次为什么选择这一认知动作、当时聚焦了什么、这一问的目标是什么
- `trace`：用户和系统实际看到的完整内容

所有内容继续保存在浏览器 localStorage，并可以导出 Markdown / JSON。

> 注意：保存的是可审计的结构化认知状态、策略选择和用户可见内容，不保存任何模型隐藏推理文本。

## 自适应而非死顺序

认知 playbook 仍然存在，但不是 UI 步骤条。例如因果解释大致遵循：

当前判断 → 机制 → 替代解释 → 隐含前提 → 证据 → 边界 → 综合

如果用户已经主动提出替代解释，系统会跳过“寻找替代解释”，直接推进下一项仍缺失的认知动作。

## V0.3 暂不做

- 不接真实大模型 API
- 不做登录 / 云同步
- 不做教师端
- 不做课程体系
- 不做人群画像或人格标签
- 不把认知诊断暴露成机械步骤条

下一阶段可以把本地 `generateQuestion()` 替换成真实模型，但必须保留“认知引擎先选动作，模型只负责生成问法”的边界。
