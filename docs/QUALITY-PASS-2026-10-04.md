# V0.5.1 核心认知质量收敛（2026-10-04）

这次只处理“认知引擎是否会错误推进”和“当前判断是否会被局部回答覆盖”，没有增加产品功能，也没有调用真实外部模型。

## 发现并修复

1. **问题分类被泛关键词抢占**
   - 旧逻辑按首次命中的关键词返回类型，例如“我为什么选择逃避冲突？”会因为“选择”先命中 `decision`。
   - 现在第一人称重复行为/情绪模式优先识别为 `self`；“选择”只有在明确决策语境下才进入 `decision`。
   - “我想弄清楚‘选择’到底是什么意思”现在归入 `concept`。

2. **“我不知道 + 动作关键词”会被误判为已完成动作**
   - 旧逻辑会把较长回答直接记为 `state_position`；同时“我想不到例外”“我不知道需要什么证据”“我不知道取决于什么条件”等会因关键词误判为完成相应动作。
   - 现在先识别“无法作答/想不到/没找到/分不清”等缺口表达；这类回答保持当前动作并进入 `stuck`，不新增 `completedMoves`。
   - 对 20 种认知动作逐一加入了“带关键词但仍然不知道”的回归用例。

3. **局部回答会覆盖原问题的当前判断**
   - 旧本地分析每轮都会把 `currentPosition` 改成最新回答，因此用户先说“我觉得会”，再回答机制和替代解释后，最终整理页可能把“另一种解释”当成当前判断。
   - 现在只有用户明确表达/修改整体判断（或进行整合）时才更新 `currentPosition`。
   - 服务端同样增加约束：模型若没有给出 `state_position` / `synthesize` 的本轮原话证据，不允许覆盖 `currentPosition`。

4. **“也可能……”会被自动当成尚未解决的问题**
   - 旧逻辑把“可能/也许/我猜”等全部写入 `uncertainties`，替代解释可能错误出现在整理页的“还有什么没想清楚”。
   - 现在区分 `tentative`（保留余地）与明确的不确定项；只有“不确定/不清楚是否/还不能判断/需要验证”等进入 `uncertainties`。

5. **原有两个评估样例暴露出旧规则的隐性跳步**
   - 决策题回答“我更看重时间和兴趣”并没有回答“更倾向哪个选择”，现在不会直接跳过 `state_position`。
   - 探索题回答“我最想先弄清……”只完成收窄焦点，不再因为句子够长而顺带完成 `state_position`。

## 验证结果

- `npm test`：**47 / 47 通过**（原项目 42 项，新增 5 项质量回归测试）。
- 新增分类边界样例：8 条。
- 新增 20 种认知动作的“伪完成”反例检查：20 / 20 均保持 `stuck` 且不新增完成动作。
- `tsc --noEmit`：通过。
- 本环境未调用 `.env.local`，未读取或使用真实 API Key，未消耗真实模型额度。
- 本环境无法重新执行 Vite/Rollup 生产构建：上传包中的 `node_modules` 来自 Windows，缺少 Linux 的 Rollup 原生可选依赖 `@rollup/rollup-linux-x64-gnu`。这不是 TypeScript 或本次改动的编译错误；源码类型检查已通过。
- 本次没有进行真实浏览器交互和真实外部模型端到端验证，这两项仍应在原 Windows 开发环境完成。
