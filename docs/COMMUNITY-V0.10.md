# V0.10 社区路径与成果回流

本版沿用 V0.9.1 的核心对话、账户、社区和导图。增加的是查看与返回思考路径的能力，同时修复两项运营权限和版本冲突问题。

## 看见一个问题怎样被继续

卡片详情可展开思考路径。来源按每页八层读取，较长路径提供“继续查看更早的来源”；子分支可继续展开和翻页。单页嵌套展示到六层后，引导打开具体卡片继续查看，避免画面无限缩进。

路径只提供可公开的卡片。来源撤回时只显示不可用标记，不返回其题目、作者或更早关系，即使当前浏览者恰好是该来源的作者。后续成果保留自己的公开内容，不因来源撤回而被删除。每次翻页重新检查从当前卡到下一页的整段公开关系；近端来源已撤回时，旧游标也会被拒绝。

GET /api/community/cards/:id/path 返回 ancestors、nextCursor 与停止原因。游标绑定当前卡片和浏览身份并由服务签名，不能修改起点后套用；服务重启后旧游标失效，需要重新展开。每次读取最多二十层，默认八层。单次展开最多追溯二百五十六层，再打开最早的卡片继续；异常环会停止读取。

## 从成果回到社区

成功发布后，本机在这次会话中保存卡片 ID 和发布时间，不添加公开字段，也不改写思考状态。发布重试不会生成重复链接。成果页提供来源路径和近期分享入口，历史页可以返回来源或最近分享的副本。

这些关联随原会话在浏览器保存和导出，仍按账户隔离。卡片是否公开，以重新打开时的服务端状态为准。旧会话没有已发布链接时仍可正常读取。新接续不会继承原作者的发布记录或结论。

## 修复运营身份抢注

原来的用户名配置会对随后注册的同名账户自动授权。现在推荐使用 COMMUNITY_MODERATOR_IDS，填入核对过的账户完整 ID。兼容旧用户名配置时，仅在服务启动时解析已经存在的账户；未建立的配置名禁止公众注册，之后建立同名账户也不会自动获得权限。

升级不自动给任何新账户授权。需要设置运营者时先建立正常账户，核对该账户的 ID，再由服务运营者设置配置并重启。网页没有授予角色的接口。

## 反馈处理同时核对内容版本

反馈记录增加 cardRevision。处理接口必须提供 expectedAt 和 expectedRevision，在同一事务中检查举报及当前卡片版本。作者编辑卡片后，旧处理请求返回 409，不写入处理记录，也不停止新版内容公开。网页会要求重新读取，离线脚本同样明确传入当前版本。

这些防护不能代替运营者阅读具体内容，也不构成自动审核系统。

## GitHub 交付

源码清单包含当前功能、锁文件、测试、评估样例和 GitHub 自动检查；不包含密钥、私人回放、数据库、备份、node_modules 或 dist。CI 配置在 Windows 和 Ubuntu 上执行同一套测试及构建，使用合成模型接口，不请求真实服务商。

本机检查与 GitHub Actions 的实际结果分别记录。配置文件存在不代表远程任务已经执行成功。
