# V0.9.1 启动与分发修正

本版处理 V0.9.0 运行包仍携带源码开发命令造成的误导。用户在不含 tests、src 和 tsconfig.json 的运行包执行测试、构建和 Vite 开发命令，分别得到零项测试、配置缺失和首页 404。之前的业务运行验收没有覆盖这些错误入口，因此不能用先前的通过结果回避这个问题。

运行包现在生成独立 package.json 和无开发依赖的锁文件。start、dev、serve、preview 都启动构建好的同源应用；test 和 build 给出中文说明并以非零状态结束，要求改用源码包。运行版 README 也独立生成，不再展示默认源码开发步骤。

启动时探测默认端口。若已有服务的健康接口确认它是就绪的反思之旅，显示已有版本和地址，说明此次没有启动当前副本，打开原页面；其他程序占用则明确报错。没有自动换端口，浏览器个人记录不会因不知情地更换地址而看似消失。缺少构建文件的运行包要求重新完整解压，不自动安装开发依赖。

本机 138 项自动测试和生产构建通过。新增检查覆盖运行包命令与非零失败状态、生成文件的哈希、已有服务识别、其他程序占用以及构建文件缺失。测试不请求真实模型。

实际解压后的命令验收记录随提交材料提供，分别核对运行包的 test、build、dev、serve、start 和重复启动；源码使用自己的测试与构建命令。运行包的测试失败提示不计作自动测试通过，源码的 138 项测试与运行包业务验证分开记录。原 V0.9.0 的技术和模型验收记录继续保留为历史证据。
